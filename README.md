# 2DFX AELS

**2DFX AELS** или **2DFX Advanced Emergency Light System** - это модификация и набор инструментов для GTA San Andreas / SA-MP, предназначенные для создания продвинутой системы спецсигналов на автомобилях экстренных служб.

Проект разрабатывается **de-facto**.

Основная цель модификации - дать авторам моделей возможность создавать не просто машины с обычными мигалками, а полноценные вариации спецтранспорта с разными уровнями оборудования, ливреями, лайтбарами, проблесковыми маячками, световыми паттернами и связанными объектами.

---

## Идея проекта

В классической GTA San Andreas система спецсигналов крайне ограничена. Игра использует стандартные точки сирены и простую логику отрисовки огней. Для обычной игры этого достаточно, но для современных модификаций спецтранспорта таких возможностей уже мало.

**2DFX AELS** создаётся как более гибкая система, которая позволяет:

- создавать большое количество самостоятельных источников света;
- задавать собственные паттерны мигания;
- привязывать к источникам света конкретные объекты модели;
- включать и выключать светящиеся элементы вместе с самими источниками света;
- создавать несколько вариантов одной машины;
- связывать разные варианты оборудования с paintjob-уровнями;
- использовать систему в GTA San Andreas и SA-MP;
- хранить данные прямо внутри `.dff` модели, без отдельных конфигурационных файлов для каждой машины.

Идея в том, чтобы адаптированная машина уже содержала в себе всю необходимую информацию для работы AELS. Автор модели настраивает её один раз в Blender, экспортирует, а игровой runtime считывает эти данные и воспроизводит их в игре.

---

## Что такое AELS

**AELS** расшифровывается как **Advanced Emergency Light System**.

Это система, в которой машина может иметь не один фиксированный набор мигалок, а несколько уровней интерпретации. Каждый уровень может описывать отдельную конфигурацию автомобиля.

Например, одна и та же модель может иметь такие варианты:

- обычная патрульная версия;
- версия с другим лайтбаром;
- версия с дополнительными задними маячками;
- supervisor-вариант;
- slicktop-вариант;
- вариант с другим оборудованием и другой ливреей.

В рамках AELS каждый такой вариант может быть связан с отдельным paintjob-уровнем и набором объектов. Runtime в игре определяет активный уровень и показывает только те элементы, которые относятся к выбранной интерпретации машины.

---

## Почему 2DFX

GTA San Andreas использует систему **2DFX** для разных визуальных эффектов, включая короны, источники света и некоторые другие эффекты окружения.

**2DFX AELS** использует эту идею как основу, но расширяет её под задачи спецтранспорта. Вместо того чтобы ограничиваться стандартными четырьмя огнями сирены, система позволяет создавать собственные источники света с настраиваемыми параметрами.

Источники света могут иметь:

- цвет;
- размер;
- дальность отрисовки;
- направление видимости;
- паттерн мигания;
- привязку к сирене или ручному включению;
- связь с объектом модели;
- собственное поведение в разных интерпретациях машины.

---

## Главная особенность

Главная особенность проекта - отсутствие отдельных конфигурационных файлов для каждой машины.

Во многих похожих системах настройки хранятся во внешних `.ini`, `.json` или других файлах. Это может быть удобно для редактирования, но усложняет установку, перенос моделей и совместимость сборок.

В **2DFX AELS** вся основная информация записывается напрямую в `.dff` файл автомобиля.

Это значит, что адаптированная модель уже содержит:

- список AELS-источников света;
- параметры каждого источника света;
- паттерны мигания;
- связи между источниками света и объектами;
- список уровней интерпретации;
- привязку объектов к уровням;
- paintjob-связи;
- runtime-метаданные для игрового ASI.

Такой подход делает модель более самодостаточной. Если машина правильно экспортирована, runtime сможет считать её данные без отдельного конфига для конкретной модели.

## Blender Addon

Для настройки машин используется собственный аддон для **Blender**.

Именно в Blender выполняется основная работа по созданию AELS-адаптации. Автор модели может открыть автомобиль, расставить источники света, настроить их параметры и привязать нужные объекты к конкретным уровням.

Аддон позволяет работать с такими элементами:

- AELS-источники света;
- кастомные blink-паттерны;
- объекты лайтбаров и оборудования;
- уровни интерпретации машины;
- paintjob-связи;
- 2DFX-параметры;
- linked light objects;
- экспорт runtime-данных в `.dff`.

Blender-часть проекта нужна не просто для визуальной расстановки точек. Она является полноценным инструментом авторинга, где создаётся логика будущего поведения машины в игре.

---

## Runtime

Игровая часть мода работает через ASI runtime.

Runtime отвечает за чтение AELS-данных из моделей и их применение в игре. Он сканирует `.dff` модели, находит AELS-метаданные и связывает их с игровыми ID автомобилей.

В игре runtime выполняет несколько ключевых задач:

- считывает AELS-данные из `.dff`;
- отключает стандартные огни сирены GTA SA;
- отрисовывает кастомные AELS-источники света;
- применяет выбранный уровень интерпретации машины;
- управляет видимостью объектов, связанных с paintjob-уровнями;
- переключает linked light objects при включении и выключении света;
- поддерживает ручное включение мигалок;
- поддерживает SA-MP vehicle ID для стабильной привязки случайных уровней.

Runtime не требует отдельного `.json` файла для каждой машины. Основные данные берутся из самой модели.

## Linked Light Objects

Одна из важных функций системы - **linked light objects**.

Это объекты внутри модели, которые привязываются к конкретным источникам света. Когда источник света активен, связанный с ним объект может визуально включаться. Когда источник света выключен, объект возвращается в обычное состояние.

Такой подход нужен для создания более реалистичных лайтбаров и маячков.

Например, можно сделать так, чтобы:

- конкретная секция лайтбара светилась только вместе со своим источником света;
- разные части лайтбара мигали независимо;
- объект менял визуальное состояние при активации;
- включались только те элементы, которые реально связаны с активным источником света;
- не подсвечивались все объекты с одинаковой текстурой одновременно.

Это особенно важно для сложных моделей, где внутри лайтбара может быть много отдельных секций, линз и световых модулей.

## Интерпретации машины

Система поддерживает несколько уровней интерпретации автомобиля.

Под интерпретацией понимается отдельный вариант машины, который может иметь свой набор объектов, оборудования и визуальных особенностей.

Одна машина может иметь до шести основных уровней. Каждый уровень может быть связан с отдельным paintjob и набором объектов.

Пример:

- Level 1 - базовый патрульный автомобиль;
- Level 2 - автомобиль с другим лайтбаром;
- Level 3 - supervisor-вариант;
- Level 4 - slicktop;
- Level 5 - версия с дополнительным оборудованием;
- Level 6 - специальная конфигурация.

К каждому уровню можно привязать объекты модели. Это позволяет использовать одну `.dff` модель для нескольких визуально разных вариантов машины.

## Random AELSPJ

В моде есть система случайного выбора AELS paintjob-уровней.

Она нужна для того, чтобы адаптированные машины могли появляться в игре с разными вариантами оборудования. При этом выбранный уровень должен быть стабильным для конкретной машины.

В SA-MP система может привязывать случайно выбранный уровень к server vehicle ID. Это позволяет избежать ситуации, когда у одной и той же машины уровень меняется при потере из вида, стриминге или повторной загрузке.

Также поддерживается настройка процентов появления уровней для каждой адаптированной модели.

Например, для одной машины можно настроить:

- Level 1 - 50%;
- Level 2 - 25%;
- Level 3 - 15%;
- Level 4 - 10%.

Настройка выполняется через внутриигровое меню `/aels`.

## In-game Menu

Для SA-MP предусмотрено внутриигровое меню `/aels`, реализованное через MoonLoader.

Меню используется для настройки случайного появления AELS-уровней у адаптированных машин.

Через меню можно:

- открыть помощь;
- включить или отключить random AELSPJ;
- увидеть список адаптированных машин;
- настроить проценты появления уровней для каждой машины;
- вручную ввести процент спавна уровня;
- сохранить настройки и отправить их в ASI runtime.
